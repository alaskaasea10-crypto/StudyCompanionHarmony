# 统一学习决策链

学伴中的首页推荐、自然语言计划、番茄钟和小测反馈必须使用同一份任务数据，不允许页面独立生成互相冲突的建议。

## 数据流

1. `LearningDecisionPolicy` 汇总学习画像、课表、考试倒计时、当前状态、未完成任务、专注记录和测验记录。
2. 策略层计算今天剩余可规划时间，并形成可解释的优先级依据。
3. `LearningPlanningOrchestrator` 调用 openPangu；服务不可用时改用 `TodayPlanService`，两种来源继续走相同流程。
4. `PlanValidator` 限制任务数量、去重、校验单项和总时长，并按优先级排序。
5. 学习页面只展示预览；用户点击“接受并同步”后，`PlanCommitService` 才写入统一任务数据。
6. 首页、计划页和番茄钟读取同一任务数组。首页只解释当前第一优先级任务，不再创建另一套计划。
7. `LearningFeedbackService` 把小测结果转换为任务反馈；错误知识点会进入统一任务数据，并成为首页下一条主动建议。

## 硬性规则

- 任务仅安排在今天，总计不超过“每日目标时长 - 今日已专注时长”。
- 当前状态为“有点累”时降低剩余预算，但不会修改已经完成的学习记录。
- 单项任务为 5 至 45 分钟，最多 4 项，标题去重。
- 模型输出必须通过本地校验才能展示；模型失败时必须明确标识“离线规则”。
- 计划只能由用户确认后写入首页、待办和番茄钟。
- 小测反馈不得重复添加相同的未完成复习任务。

## 推荐优先级

1. 小测刚暴露的薄弱点。
2. 已确认计划中尚未完成的第一项。
3. 用户手动添加的任务按其在计划中的顺序执行。
4. 所有任务完成后，首页转为休息与复盘建议。
